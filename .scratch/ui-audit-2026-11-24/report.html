Verified findings

P1. UTC changes the user's task day early

Location: src/taskApp.tsx:8. Category: implementation integrity.

new Date().toISOString().slice(0, 10) supplies UTC to Due Today, Past Due, and task badges. At 20:00 on November 24 in Detroit, the app supplies November 25. Today's tasks can therefore appear overdue and tomorrow's tasks can appear due today. The calculation was verified with the instant 2026-11-25T01:00:00Z, which formats as November 24 in America/Detroit. The shell also has no scheduled local-midnight refresh.

Recommendation: derive the calendar date in the user's timezone and refresh it at local midnight or when the page becomes visible. Verify both sides of midnight in positive and negative UTC offsets. No WCAG claim. Suggested command: $impeccable harden.

P2. Inline editing loses the keyboard's position

Location: src/taskSurface.tsx:1009 and src/taskSurface.tsx:953. Category: accessibility.

Clicking Edit removes its button and renders the form without moving focus to Title. Browser inspection confirmed document.activeElement === document.body. The next Tab skipped the new form and landed on the next task's Complete Task button. Cancel also left focus on the body. Keyboard users must navigate backward to find the form.

Recommendation: focus Title when editing starts, then restore focus to that row's Edit button on cancel/save. Choose a predictable surviving target after row removal. Relevant standard: WCAG 2.4.3, Focus Order. Suggested command: $impeccable harden.

P2. Required titles are not exposed as required controls

Location: src/taskSurface.tsx:395 and src/taskSurface.tsx:903. Category: accessibility.

Create and Edit title inputs have neither required nor aria-required. The visible label is only “Title”; the required instruction lives in placeholder text and an error after validation. Browser inspection confirms the create input's required property is false.

Recommendation: expose required status programmatically and keep a persistent visible instruction. Preserve the existing trimmed-title check and linked inline error. Relevant guidance: WCAG 3.3.2, Labels or Instructions. This is a semantics gap; no screen-reader session was run to assert a specific announcement failure. Suggested command: $impeccable harden.

P2. Private task content starts after hydration and another request

Location: src/taskSurface.tsx:136, src/taskSurface.tsx:149, and src/taskSurface.tsx:186. Category: performance.

Query state starts loading and the client effect initiates task retrieval. The initial private route cannot render task data until JavaScript, test identity loading, and the task request finish. Mobile lab LCP is 3.4s with uncompressed serving, while desktop is 0.7s. The same loading path also replaces existing rows with skeletons during refresh.

Recommendation: first measure with the intended hosting compression and real authenticated sessions. If the delay persists, investigate authenticated route loading or prefetching and retain existing rows during refresh. Preserve per-user ownership and avoid speculative memoization. No WCAG claim. Suggested command: $impeccable optimize.

P3. The design reference is behind the implementation

Location: DESIGN.md, .impeccable/design.json, src/styles.css:5, and src/taskSurface.tsx:25. Category: implementation integrity/theming documentation.

The design reference specifies 40px controls and pure-white surfaces. The running app uses 44px controls and a slightly tinted OKLCH surface. The runtime choices are consistent and accessible, but future work following the reference could reintroduce obsolete sizing or colors.

Recommendation: document the current tokens and component dimensions when design documentation upkeep is requested. Do not change the working 44px controls to match stale text. Suggested command: $impeccable document. No documentation drift was repaired in this audit.
